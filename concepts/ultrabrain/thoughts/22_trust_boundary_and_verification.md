# Trust Boundary And Verification

UltraBrain should not claim that hallucinations disappear. The stronger claim is:

```text
unsupported model proposals cannot become trusted memory
```

This is the trust boundary:

```text
LLM output -> proposal
tool/user/oracle evidence -> trusted evidence
policy gate -> trusted belief
answer -> proof trace
```

The verifier is not a decoration. It is the write gate into long-term trusted
memory.

## Belief Types

The system should distinguish:

- proposal: generated by a model or teacher, not trusted yet
- evidence: raw tool/user/oracle output with a digest and provenance
- belief: a claim promoted by policy
- rejected claim: a claim that failed verification
- superseded claim: a formerly active belief replaced by stronger evidence

## Strong Domains

Verification is strongest in domains where reality can be checked by tools:

- math: substitution, symbolic solvers, proof assistants
- code: tests, type checks, linters, compilers, runtime traces
- files: git diff, filesystem checks, content hashes
- infrastructure: config validators, policy engines, cloud dry-runs

Verification is harder in domains like history, philosophy, and language. These
need source tracking, disagreement tracking, and uncertainty labels rather than
simple true/false gates.

## Rule

The system can learn fast into memory, but trusted memory must be evidence-backed.

```text
no evidence -> no trusted belief
no trusted belief -> no clean training example
```
