## 1. Context (60 seconds)

UltraBrain-Code is a **verifier-grounded code engine**: an adversarially-hardened **gate** is the
asset; every neural net (an LLM *or* the from-scratch diffusion model) is a **demoted, untrusted,
OS-isolated proposer**. Only gate-certified outputs are trusted. Trust boundary:
`no evidence → no trusted belief → no clean training example`.

Code status: **Slices 1, 2, 2b, 3 are complete, tested (87 passing), Codex- + workflow-reviewed,
and tagged `ultrabrain-code-v0.1` (local only — nothing pushed/merged).** The architecture is done.

**What is NOT done — and is the entire reason this machine exists:** the headline product claim is
still *unmeasured*. Everything proven so far used a zero-ML mock proposer and a Shakespeare
checkpoint that certifies 0/11. Nobody has yet run a **real Qwen3-Coder-14B fine-tune** and measured
the one claim the whole project is built to defend:

> *On contamination-controlled, hard-test-verified tasks within its trained task family,
> UltraBrain-Code solves more tasks per GPU-hour than the base model run beside it —
> a **cost-per-solved-task** win.*

Producing that number is the **definition of done** for this session (see §8).

## 3. ⚠️ CRITICAL: run under WSL2, not native Windows

`run_verified_search.py` executes **untrusted model output** and **fails closed** unless the POSIX
`resource` module is importable (see `run_verified_search.py:88-92` — *"Run where the `resource`
module works"*). **Native Windows Python has no `resource` module**, so `--proposer llm` will refuse
to run there. vLLM and bitsandbytes are also Linux-first and fight native Windows.

**→ Do all of this inside WSL2 (Ubuntu) with CUDA-on-WSL.** That gives you, in one environment:
the POSIX isolation the gate requires, vLLM, and bitsandbytes.

```powershell
# (Windows PowerShell, admin — one time)
wsl --install -d Ubuntu
# Install the NVIDIA CUDA-on-WSL driver on the WINDOWS side (not inside WSL):
#   https://developer.nvidia.com/cuda/wsl  → reboot
```
```bash
# (inside WSL2 Ubuntu, from here on)
nvidia-smi            # MUST show the RTX 5080. If not, the WSL CUDA driver isn't installed.
```
If `nvidia-smi` fails inside WSL, stop and fix the driver before anything else — every step below
depends on it.

## 5. Step-by-step (each step: what / command / success signal)

### Step 0 — sanity-check the clone before burning GPU ($0, ~1 min)
Confirm the repo arrived intact and the gate still works, with zero ML:
```bash
python3 -m pytest -q                                   # expect: 87 passed
python3 experiments/exp_coverage_vs_singleshot.py      # expect: THESIS SUPPORTED
```
If these don't pass, the clone is broken — fix that first, don't proceed.

### Step 1 — serve Qwen3-Coder-14B for sampling
The RTX 5080 has **16 GB VRAM**. Full-precision 14B (~28 GB) will NOT fit — **serve a quantized
build** (AWQ/GPTQ) so weights + KV cache fit:
```bash
vllm serve Qwen/Qwen3-Coder-14B-AWQ --port 8000 --max-model-len 4096
#   (substitute the exact AWQ/GPTQ repo id that exists; or serve via `ollama run qwen3-coder:14b`)
```
Success: `curl -s localhost:8000/v1/models` lists the model.

### Step 2 — forge REAL verified traces (replaces the 4 KB mock seed)
Only gate-certified solutions are written to `data/verified_traces.jsonl` + the HMAC ledger.
Runs **OS-isolated + fail-closed** (do NOT pass `--unsafe`):
```bash
python3 run_verified_search.py --proposer llm \
    --base_url http://localhost:8000/v1 --model Qwen/Qwen3-Coder-14B \
    --tasks tasks/micro_codebench.jsonl --n 16
```
Success: `data/verified_traces.jsonl` grows with real certified traces; ledger chain verifies.
Then **stop vLLM** (`Ctrl-C`) — you cannot serve a 14B model *and* fine-tune on 16 GB at once.

### Step 3 — the QLoRA fine-tune (THE CUDA-only step)
```bash
# validate the pipeline first (no GPU touched):
python3 train_qlora.py --dry_run
# the real run (defaults are tuned for 16 GB: batch 1, grad_accum 8, max_seq 1024, r16):
python3 train_qlora.py --data data/verified_traces.jsonl --out checkpoints/qwen3coder14b-lora
```
Success: `saved LoRA adapter -> checkpoints/qwen3coder14b-lora`. Watch `nvidia-smi` — if it OOMs,
drop `--max_seq` to 768 or `--lora_r` to 8.

### Step 4 — MEASURE THE CLAIM (the actual deliverable)
Eval is measurement only — it never writes beliefs. Compare base vs fine-tuned on the verifiable
slice and record **cost-per-solved-task** for each:
```bash
# baseline (re-serve base or point at it), then fine-tuned (serve base + LoRA adapter):
python3 eval_code.py --proposer llm --base_url http://localhost:8000/v1 \
    --model Qwen/Qwen3-Coder-14B --tasks tasks/micro_codebench.jsonl
```
Record: tasks solved, tokens/GPU-seconds per solved task, base vs fine-tuned. **This delta is the
whole point** — write it into `RELEASE_NOTES.md` under a new "Measured on RTX 5080" section.

### Step 5 (optional) — the full ReST-EM loop
```bash
python3 self_improve.py --rounds 3     # collect → train → eval, repeated
```

### Step 2b (optional, CUDA-nice but the Mac can also do this) — code-train the diffusion FIM head
The shipped diffusion checkpoint is Shakespeare-trained (certifies 0/11). Train it on code to turn
that into real fills. Needs `data/code_corpus.txt` (does not exist yet — assemble one, e.g. from the
repo's own `.py` files or a permissively-licensed code set):
```bash
python3 train.py --corpus data/code_corpus.txt      # -> checkpoints/diffusion.pt (+ tokenizer.json)
python3 eval_code.py --proposer fim --tasks tasks/micro_fim.jsonl --n 8   # 0/11 should start moving
```
The gate is unchanged — a code-trained checkpoint slots in with no gate change.
